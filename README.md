# 교무수첩 서버 저장 앱

첨부한 교사업무자동화플랫폼 v1의 화면과 기능을 기반으로 만든 배포용 앱입니다.
GitHub는 소스 보관, Render는 웹 서버 실행, Neon PostgreSQL은 기록 저장을 담당합니다.
로그인·비밀번호 없이 한 공용 작업 공간을 사용합니다. 배포 주소에 접속한 누구나 같은 자료를 조회·수정·삭제할 수 있습니다.

## 1. Neon 준비

1. Neon에서 프로젝트와 데이터베이스를 만듭니다.
2. 프로젝트의 Connect 화면에서 PostgreSQL 연결 문자열을 복사합니다. Node.js용 연결 문자열 또는 pooled 연결 문자열을 사용할 수 있습니다.
3. `postgresql://...` 전체 문자열을 Render의 `DATABASE_URL`에 넣습니다. SSL 옵션도 유지하세요.

앱 비밀번호는 없지만 데이터베이스 접속에 필요한 인증정보는 연결 문자열에 들어갑니다. 이 값은 Render 환경변수에만 넣고 GitHub에 올리지 마세요. 테이블은 서버 첫 실행 때 자동 생성합니다. 연결 계정에는 테이블 생성·조회·수정 권한이 필요합니다.

## 2. GitHub에 업로드

1. ZIP을 압축 해제합니다.
2. GitHub에서 새 저장소를 만듭니다.
3. 압축 해제 폴더 **안의 파일과 폴더**를 올립니다. 저장소 첫 화면에 `package.json`, `server.js`, `render.yaml`, `public`이 보여야 합니다.
4. ZIP 자체를 올리거나 `public/index.html`만 올리는 방식으로는 서버가 실행되지 않습니다.

## 3. Render 배포

1. Render에서 **New → Blueprint**를 선택하고 GitHub 저장소를 연결합니다.
2. 포함된 `render.yaml`을 사용합니다.
3. `DATABASE_URL` 입력란에 Neon 연결 문자열을 붙여넣고 배포합니다.
4. 배포 완료 후 Render의 서비스 주소를 엽니다.

직접 **Web Service**로 만들 때는 다음 값을 사용합니다.

| 항목 | 설정 |
|---|---|
| Runtime | Node |
| Root Directory | 저장소 루트라면 비워둠 |
| Build Command | `npm install --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Environment Variable | `DATABASE_URL` = Neon 연결 문자열 |

`package.json`에서 Node.js 24를 지정했습니다. Render의 `PORT`를 자동 사용합니다. Static Site가 아니라 Web Service로 만드세요. Blueprint에는 free 플랜이 지정되어 있으며 실제 계정에서 사용 가능한 요금제를 확인하세요.

## 4. 사용 및 기존 자료 이동

- 처음에는 예시 학생 없이 빈 작업 공간으로 시작합니다.
- 기존 HTML에서 **데이터 관리 → JSON 백업 내려받기**를 실행합니다.
- 배포된 앱에서 **데이터 관리 → JSON 백업 가져오기**로 그 파일을 불러옵니다.
- 상단에 **서버 저장 완료**가 표시된 뒤 창을 닫으세요. 버튼을 누른 직후에는 아직 서버 저장 중일 수 있습니다.
- 다른 PC나 휴대전화에서도 같은 Render 주소로 접속하면 저장된 기록을 불러옵니다.
- 다른 창의 변경은 **최신 자료 불러오기**로 확인합니다. 실시간 공동 편집 기능은 아닙니다.
- 두 창에서 동시에 수정하면 뒤늦은 저장은 충돌로 차단됩니다. 미저장 자료를 내려받고 최신 자료를 불러온 후 필요한 변경을 다시 입력하세요. 자동 병합하지 않습니다.
- 네트워크 장애 때는 현재 창의 변경을 유지하고 다시 저장할 수 있습니다. 창을 닫거나 브라우저가 종료되기 전에 백업하세요. 오프라인 영구 저장 기능은 없습니다.
- 상단 **미저장 자료 다운로드**는 핵심 기록용 JSON입니다. 설정·글꼴까지 포함하려면 데이터 관리의 전체 백업을 사용하세요. JSON 가져오기는 기존 기록 전체를 교체합니다.

## 저장 범위

학생, 상담, 연락, 누가기록, 수행평가, 성적, 교과 관찰기록, 업무 일정, 학교, 학년도, 바로가기와 휴일·화면 설정 및 삭제 복구함은 서버에 저장합니다.
원본의 사용자 업로드 글꼴 파일은 브라우저 IndexedDB에 남습니다. 다른 기기에서는 글꼴 파일을 다시 선택하거나 글꼴을 포함한 전체 백업을 복원하세요. PC 설치 글꼴도 해당 PC에 설치되어 있어야 합니다.

데이터는 PostgreSQL의 `teacher_workspace` 테이블에 JSONB로 보관합니다. 저장 요청은 revision이 일치할 때만 원자적으로 반영합니다. Render 파일 저장소에는 업무 자료를 쓰지 않으므로 서버 재시작·재배포 후에도 같은 Neon 데이터베이스를 연결하면 자료가 유지됩니다.

## 로컬 실행

Node.js 24와 npm을 설치한 후 프로젝트 폴더에서:

```sh
npm install
```

`.env.example`을 `.env`로 복사하고 실제 Neon 연결 문자열을 넣습니다.

```sh
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다. HTML을 더블 클릭해서 실행하지 마세요.

## 검사 및 문제 해결

`npm test` 또는 `node --test`로 API 테스트를 실행합니다.
제작 시 API 저장·조회, 충돌 방지, 입력 검증, 다른 출처 요청 차단, 환경파일 접근 차단을 테스트했습니다. Edge 브라우저에서 화면 초기화, 학교 등록·서버 저장, 두 번째 창의 자료 로드, 충돌 표시도 테스트했습니다. 테스트는 메모리 저장소로 수행했으며 실제 Render 배포·Neon 연결 검증은 계정 연결 후 필요합니다.

- 서버가 시작되지 않음: Render 로그와 DATABASE_URL을 확인하세요. Neon의 데이터베이스·역할·연결 옵션을 확인하세요.
- 처음 접속이 느림: 서비스가 시작된 뒤 다시 시도하세요.
- 저장 실패: 상단의 다시 저장을 누르세요. 반복되면 미저장 자료를 다운로드하세요. API 요청 크기 제한은 25MB입니다.
- 다른 기기에서 새 기록이 안 보임: 원래 기기의 서버 저장 완료를 확인하고 새로고침하세요.
- 글꼴 백업 실패: 현재 기기에 해당 글꼴 파일을 다시 등록하세요.
