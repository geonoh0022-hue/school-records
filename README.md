# 교사업무자동화플랫폼 V3.8 · 오프라인 지원 배포판

V3.8_개인일정추가 HTML을 기반으로 합니다. 비밀번호나 로그인 없이 사용하며, 정상 저장·완료 시간 안내는 숨깁니다. 오프라인·실패·충돌 안내만 표시합니다.

## 기존 서버 업데이트
1. 먼저 기존 앱의 데이터 관리에서 JSON 전체 백업을 다운로드합니다.
2. ZIP 안 파일을 기존 GitHub 저장소 최상위에 덮어쓰고 커밋합니다. public/sw.js도 반드시 추가합니다. 이번에는 HTML뿐 아니라 cloud.js와 server.mjs도 변경되었습니다.
3. Render에서 새 커밋을 배포합니다. 기존 Supabase SQL과 환경 변수는 그대로 사용합니다.
4. 인터넷이 연결된 상태에서 기존 앱 창을 모두 닫고 새로 엽니다. ‘오프라인 사용 준비가 완료되었습니다’ 안내를 기다립니다.
5. 시험 기록을 입력하고 인터넷을 끈 후 앱을 닫았다 다시 열어 확인하세요. 연결 복구 후 새로고침하거나 다른 기기에서 서버 반영 여부를 확인합니다.

## 오프라인 사용
- 같은 기기, 같은 Edge/Chrome 프로필, 같은 배포 주소에서 사용할 수 있습니다. 앱 설치는 필수가 아닙니다.
- 처음 한 번은 온라인에서 접속하여 화면 파일과 서버 자료를 내려받아야 합니다. 준비 안내는 화면 파일 캐시 완료 기준이며, 앱 화면도 정상적으로 열려야 자료가 준비된 상태입니다.
- 주요 업무 자료를 로컬 저장소에 저장합니다. 오프라인 변경은 창을 닫고 컴퓨터를 재시작해도 남으며, 앱이 열린 상태에서 연결이 복구되면 자동 전송합니다. 서버 일시 장애도 같은 방식으로 처리합니다.
- 앱을 닫아 둔 동안에는 전송하지 않습니다. 다음 실행 때 다시 시도합니다.
- 기기별로 한 창만 편집할 수 있습니다. 다른 창이 열려 있으면 기존 창을 닫고 새로고침합니다.
- 다른 기기가 먼저 수정한 경우 서버 자료를 덮어쓰지 않습니다. ‘이 기기 자료 백업’ 후 ‘서버 자료 불러오기’를 눌러 최신 자료를 받고 필요한 내용을 수동 반영하세요. JSON 가져오기는 병합이 아닌 전체 교체입니다.
- AI 초안, 온라인 맞춤법, 외부 공휴일 조회, 외부 링크는 인터넷이 필요합니다. API 키는 기존처럼 화면에서 설정합니다.
- 글꼴·화면 설정 등 기존 브라우저 전용 설정은 서버 동기화 대상이 아닙니다.
- 브라우저의 사이트 데이터 삭제, 프로필 삭제, 저장 공간 부족으로 로컬 자료와 캐시가 없어질 수 있습니다. 정기적으로 JSON 백업을 보관하세요. 비공개 창은 사용하지 마세요.
- 새 버전 배포 시 모든 앱 창을 닫았다 다시 열면 대기 중인 화면 업데이트가 적용됩니다. 이후 코드 변경 시 public/sw.js의 CACHE 버전도 변경해야 합니다.

## 처음 배포하는 경우
1. Supabase 프로젝트 SQL Editor에서 supabase/schema.sql 전체를 실행합니다.
2. 이 ZIP 안의 파일을 GitHub 저장소 최상위에 업로드합니다.
3. Render → New → Blueprint에서 저장소를 연결합니다.
4. SUPABASE_URL에는 https://프로젝트ID.supabase.co, SUPABASE_SECRET_KEY에는 같은 프로젝트의 sb_secret_... 또는 service_role 키를 입력합니다.
5. 배포한 HTTPS 주소를 엽니다. 서버 비밀 키나 실제 .env는 GitHub에 올리지 않습니다.

로그인이 없으므로 주소를 아는 누구나 서버 자료를 조회·수정할 수 있습니다. 오프라인 지원은 접근 제한 기능이 아닙니다.

## 검증 및 제한
Node.js 22.16 이상에서 npm ci, npm test, npm start로 실행할 수 있습니다. 로컬 실행은 .env.example을 .env로 복사하여 설정합니다. HTML 더블클릭은 지원하지 않습니다.

모의 브라우저/서버 환경에서 오프라인 재실행, 재연결 전송, 충돌 보존, 응답 유실 복구, 서버 검증을 확인했습니다. 실제 Render 배포와 Edge 오프라인 동작은 사용자 환경에서 위 절차로 최종 확인해야 합니다.
